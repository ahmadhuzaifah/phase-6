# Technical SEO Report

## Build snapshot

- Static pages generated: 781
- Canonical site: `https://dhaphase6lahore.pk`
- Sitemap: generated by `@astrojs/sitemap` during build
- Robots file: `public/robots.txt`

## Coverage

Shared metadata is provided by `src/components/seo/Meta.astro`. Page-level JSON-LD covers the homepage, articles, properties, places, breadcrumbs, FAQs, and other entity pages through existing templates and page data. Reusable schema constructors are available in `src/utils/seo/` for new pages.

The generated sitemap applies priority and change-frequency rules in `astro.config.mjs`, with higher priority for pillar guides, market dashboards, and key intent pages.

## Internal links

Run `npm run link:audit` after a build. The script checks generated HTML for broken internal links, counts inbound links, and reports orphan or low-link pages in `internal-link-report.md`.

The current audit scanned all 781 generated pages and found 951 broken internal links, 70 orphan pages, and 106 pages with fewer than two inbound links. These are existing route/data-link issues to remediate in a dedicated link-fix pass; they are recorded rather than concealed by the audit.

## Performance findings

- The hero image is preloaded and has intrinsic dimensions.
- Card, gallery, map, and directory images are lazy-loaded where appropriate.
- Shared CSS is imported once through `BaseLayout.astro` and Astro inlines styles according to the configured build strategy.
- Google Fonts use preconnect hints; font loading remains an external network dependency.
- The site is static, so page rendering does not require a runtime server or client-side framework bundle.

## Remaining issues

- The existing `seo:audit` currently reports legacy metadata/schema issues alongside duplicate titles and descriptions; its output should be triaged before changing page-level SEO.
- Some legacy pages still use bespoke HTML shells and should be migrated to `PageLayout.astro` in a separate snapshot-tested effort.
- The data model is JSON-first; validation should be added at import boundaries if external feeds become automated.
- Browser-level Lighthouse and Core Web Vitals measurements require a deployed or locally served site and are not inferred from the static build alone.
